# Protocol Studio

응용·전송 계층의 프로토콜을 정의하고 하위 통신 환경을 설정해 가상 참여자 사이에서 검증하는 도구다. 기존 예제에서 메시지 구조와 흐름을 살펴보고 사용자 정의 사본으로 실험하는 것을 목표로 한다.

첫 버전의 P0~P7 구현과 필수 검증을 완료했다. 화면에서 메시지·상태·규칙·시나리오를 편집하고 가상 참여자 A/B로 실행해 시퀀스·상태·기대 결과·원인을 확인할 수 있다. 실험 시작에서 출처·버전·지원 범위가 있는 아홉 예제의 사용자 사본 또는 빈 실험을 연다. 데이터그램 손실·중복·지연 변동과 스트림 합쳐 읽기·종료를 설정하고, ACK 손실·재전송·중복 제거를 관찰할 수 있다. HTTP GET·POST·분할/오류/지연 시나리오와 TCP 정상 연결 수립을 실제 바이트·필드·상태로 관찰한다. 초안·미완성 JSON·실행 snapshot과 결과는 이 브라우저에 자동 저장하며 파일로 가져오고 내보낼 수 있다. 과거 기록 탐색과 당시 snapshot 재실행을 구분한다. 저장 오류 때 메모리 작업을 유지하고 재시도·내보내기를 제공한다. 전체 HTTP/TCP 구현은 아니다. 전체 진행 상태는 [문서 지도](docs/index.md), 편집·실행 방법은 [P3 문서](docs/design-docs/p3-workspace.md)와 [P4 환경·재전송](docs/design-docs/p4-environments.md), 표준 지원 경계는 [P5 문서](docs/design-docs/p5-standard-examples.md), 저장·복구 경계는 [P6 문서](docs/design-docs/p6-persistence-replay.md)에서 확인한다.

프로토콜 보기에서 상태·규칙을 자동 상태도로 살펴볼 수 있다. 화살표를 선택하면 이벤트·조건·동작을 보고 편집 위치로 이동한다. 실행 보기의 **실행 상태도 보기**에서 A/B의 현재 상태·최근 적용 규칙과 과거 기록 위치를 확인한다. 실행 당시 정의가 초안과 다르면 편집 이동을 막아 과거 기록을 보존한다.

실행 보기의 **통신 시퀀스 보기**를 열면 A/B 사이의 송신·실제 하위 수신과 손실·중복·연결 차단을 화살표로 확인한다. 행을 선택해 실행 당시 메시지 필드·바이트·원인과 직접 후속 기록을 본다. 타이머 만료·타임아웃 실패·재전송 후보를 구분하며, 과거 기록에서는 재생 위치까지의 관찰만 그린다. 한 페이지 30행과 가로 스크롤·Enter/Space 선택을 지원한다.

두 실행 그림은 선택을 공유한다. 시퀀스 이벤트를 고르면 **연결된 상태도 보기**에서 해당 참여자·규칙·실제 전후 상태/변수를 확인한다. 상태도의 규칙이나 상태를 고르면 관련 회차를 20개씩 살펴보고 **시퀀스에서 관련 기록 보기**로 이동한다. 같은 규칙의 여러 실행과 미관찰 전이를 구분한다. 선택 시 자동 진행을 멈추며, 기록 자동 재생은 두 그림의 선택과 함께 이동한다.

초안은 **프로토콜 → 그림에 상태 추가**로 작성한다. **전이 연결 시작** 후 출발·도착 상태와 발생 이벤트를 고르면 새 규칙을 만든다. 선택 상태/규칙의 기존 폼을 옆 편집기에서 수정하며, 좁은 화면에서는 아래에 표시한다. **전체 목록에서 편집**으로 돌아갈 수 있고 연결은 Escape/취소로 끝낸다. 기존 규칙과 겹치면 조건을 구분해 진단을 해결한다. 자기 전이는 처음에는 명시적 무시로 생성하며, 동작을 추가하려면 이를 해제한다. 실행 당시 상태도는 읽기 전용이다.

**반복 실험**에서는 지연·데이터그램 손실률의 조건마다 같은 seed 목록으로 실행한다. 빈 조건은 초안 값을 유지하며 시작 시 프로토콜·시나리오를 고정한다. 두 실행 묶음의 기대 조건 통과율·미판정·송신/타이머 만료·가상 완료 시간을 비교하고, 조건의 개별 실행을 기존 그림에서 재생한다. 같은 초안에서 조건 입력은 화면을 오가도 유지된다. 실행 기록은 로컬 저장·bundle에 포함되며 총 100개·64 MiB 한도다. 중단·한도 도달을 실패에 합치지 않고 미실행·삭제를 별도로 표시한다. 가상 완료 시간은 통과 실행에서 성공 종료한 참여자들의 마지막 종료 시각이며 표본 수를 함께 표시한다. 실제 네트워크 성능 측정은 아니다.

실행 보기에서 이벤트나 상태도 회차를 선택한 뒤 **실행 이유 설명**을 열면, 규칙 후보의 참/거짓과 실제 비교 값·AND/OR에서 생략된 분기를 확인한다. 변수 대입은 동작 순서대로 식의 입력 값·계산 결과와 최종 변경을 보여준다. 현재 초안 대신 실행 당시 snapshot을 사용하고 계산 결과를 기록된 전후 값과 대조한다. 여러 전이가 연결되면 회차를 고르며, 과거 기록과 반복 실험의 개별 실행에서도 사용할 수 있다. 너무 큰 계산·부족한 기록·지원하지 않는 버전·불일치는 명시하고 실행 결과와 저장 데이터는 변경하지 않는다.

**시나리오 묶음**에서 입력·기대 조건·환경·seed를 사례로 저장/복제하고 공통 프로토콜로 활성 사례 전체를 검증한다. 수정 후 다시 실행해 동일한 사례 조건의 새 실패·개선을 비교하고, 조건 변경·미판정·미실행을 구분한다. 개별 결과는 기존 그림과 실행 이유 설명에서 재생한다. 초안당 최대 20사례이며 로컬 저장·bundle과 기존 기록 100개·64 MiB 한도를 따른다.

실행의 **기대 조건 진단**에서 기대값과 관찰값, 관련 상위 전달·상태 전이·종료 시각을 비교한다. **연결 근거**는 직접 원인·합쳐진 송신·같은 타이머 세대의 시작을 따라가며, 환경 장애·타이머 만료 등의 참고 관찰은 별도로 표시한다. **기록 보기**와 **실행 설명 보기**로 시퀀스·관찰된 규칙에 이동한다. 과거 cursor와 당시 snapshot을 사용하고, 미완료·기록 불일치·계산 상한은 확정 실패 원인과 구분한다.

실행 이벤트·시퀀스를 선택하고 **메시지 구조 보기**를 열면 HTTP 시작 줄·헤더·본문, JSON envelope/필드/구분자와 논리 패킷 구조를 살펴볼 수 있다. 영역이나 필드를 선택하면 실제 전송 byte 범위와 hex/ASCII를 강조하고 해당 페이지로 이동한다. 수신 청크·값만 있는 이벤트·큰 JSON은 관찰 범위와 분석 한계를 표시하며 전송 bytes를 재생성하지 않는다. 큰 원본은 256 bytes씩 탐색하고 과거 기록에는 당시 정의를 사용한다.

실행의 **중단점과 조건부 정지**에서 상태 진입·메시지 수신(해석 완료)·전이 후 변수 조건을 설정한다. 일치하면 안전한 처리 단계 끝에서 멈추고 근거·관련 기록·실행 설명을 확인한다. **이 실행 계속**은 현재 snapshot의 큐·타이머를 유지하고, 과거 자동 재생도 같은 조건으로 정지한다. 최대 20개 설정은 현재 탭에서 실험별로 유지하며 새로고침 시 초기화한다. 반복/회귀 일괄 실행에는 적용하지 않고 개별 기록 재생에서 사용한다.

## 로컬 개발

Node.js 버전은 [.nvmrc](.nvmrc), pnpm 버전은 [package.json](package.json)의 `packageManager`를 따른다. 설치된 nvm을 사용해 다음 명령을 저장소 루트에서 실행한다.

```sh
nvm use
corepack pnpm install --frozen-lockfile
corepack pnpm dev
```

개발 서버는 기본적으로 `127.0.0.1:5173`에서 시작한다. 포트가 사용 중이면 Vite가 안내하는 주소를 확인한다. 외부 서버·기기나 credential은 필요하지 않다. Node.js가 없다면 먼저 `nvm install`을 실행한다.

## 검사

```sh
corepack pnpm exec playwright install chromium firefox
corepack pnpm check
```

`pnpm check`는 lint·포맷·strict 타입 검사·Node 단위/통합 테스트·문서 검사·빌드·Chromium/Firefox E2E와 전용 Chromium 응답성 검사를 순서대로 수행한다. 최초 Playwright 브라우저 설치에는 네트워크가 필요하다. Linux CI에서는 해당 환경의 브라우저 OS 의존성도 준비해야 한다. E2E는 빌드된 결과를 고정 포트 4173의 전용 preview 서버에서 검사하며 기존 서버를 재사용하지 않는다.

데스크톱 Chromium/Firefox, 390/768/1440px의 배치·키보드를 검사한다. Safari·실기기 모바일은 미검증이다. 대형 trace는 200행씩 탐색하고 이벤트 상세는 미리보기로 표시하며 전체 데이터는 bundle에 보존한다. 응답성 기준과 한계는 [P7 문서](docs/design-docs/p7-validation.md)를 따른다.

세부 명령과 로컬/CI 검증 범위는 [개발 기준](docs/development.md), v1 단계별 목표는 [실행 계획](docs/exec-plans/completed/20261030-1641-layered-protocol-v1.md)을 따른다.
