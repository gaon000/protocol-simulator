# 계층별 프로토콜 설계·이해·검증 도구 v1

상태: Accepted
합의일: 2026-10-30
구현 상태: P5 폼·실행·장애 환경, 제한된 HTTP/1.1·TCP 연결 예제와 출처·버전·사용자 사본까지 연결했다. 영속 저장은 후속 단계다. 이 문서는 v1 전체 제품 범위이며 전체 실행·테스트 완료 기록이 아니다.

## 목적과 사용자

기존 프로토콜의 구조와 통신 흐름을 살펴보고, 자기 프로토콜을 정의하거나 기존 예제의 사본을 수정해 가상 참여자 사이에서 검증하는 도구다. 주요 사용자는 프로토콜을 이해하거나 설계하려는 개발자와 학습자다. 기존 프로토콜의 정확한 지원 범위를 표시하고, 실행 결과를 해당 규칙·환경·시나리오에 연결한다.

첫 버전은 데스크톱 웹 작업 공간을 기준으로 설계한다. 제품 목적과 기능 범위는 사용자와 합의했으며, 도구와 기초 계약은 [P0 확정 계약](../design-docs/p0-execution-contract.md)에 기록했다.

## 사용자 행동

1. 예제 또는 내 실험을 열거나 새 실험을 만든다.
2. 응용 계층 또는 전송 계층을 선택한다.
3. 양쪽 참여자의 프로토콜과 호환되는 하위 통신 서비스를 선택한다.
4. 메시지·패킷 형식, 상태·변수, 통신 규칙을 편집한다.
5. 하위 환경의 지연·손실 등 조건과 실행 시나리오·기대 조건을 정한다.
6. 전체 실행 또는 단계 실행으로 통신을 관찰한다.
7. 이벤트를 선택해 데이터, 적용 규칙, 환경의 처리와 상태 변화를 확인한다.
8. 환경을 바꿔 다시 실행하거나 실험을 저장·내보내 다른 세션에서 재개한다.

## 제품 정책과 예외

### V1-001: 실험 단위와 계층

하나의 실험은 프로토콜 정의, 하위 환경, 시나리오, 기대 조건으로 구성한다. 참여자는 A와 B 두 개이며 각자의 상태와 변수를 소유한다. 동일한 정의를 양쪽에서 재사용해도 실행 상태는 공유하지 않는다.

응용·전송 두 계층의 프로토콜을 각각 정의할 수 있고 한 번의 실행은 한 계층을 대상으로 한다. 하위 계층은 서비스 모델로 제공한다. 여러 사용자 정의 계층의 연결 실행은 후속 범위다. 계층 이름과 요청·응답 같은 통신 패턴은 별개의 속성이다. 응용 계층 프로토콜도 데이터그램을 사용할 수 있다.

### V1-002: 하위 서비스와 호환성

| 하위 서비스 | 보장 | 설정 가능한 조건 |
| --- | --- | --- |
| 바이트 스트림 | 연결이 유지되는 동안 바이트의 순서와 중복 없는 전달. 메시지 경계는 보존하지 않음 | 방향별 전달 지연, 읽기 청크 크기·합치기, 정상 종료·연결 실패 시점 |
| 데이터그램 | 전달된 패킷의 경계 보존. 전달 성공·순서는 보장하지 않음 | 방향별 지연·지연 변동, 손실률, 중복률, 특정 전송 패킷 손실 |

프로토콜이 요구하는 서비스와 환경이 제공하는 서비스가 다르면 실행 전에 오류를 표시한다. 스트림에 임의의 바이트 손실·중복·순서 역전을 적용하지 않는다. 연결 실패는 명시적인 종료·오류로 전달한다. 데이터그램의 순서 역전은 전달 지연 차이로 재현한다.

대역폭, 혼잡, MTU, 체크섬 오류와 비트 손상은 첫 버전의 환경 설정에 포함하지 않는다. 환경의 전달 지연과 참여자의 처리·응답 대기 시간은 별도 항목으로 표시한다.

### V1-003: 프로토콜 정의와 편집

- 형식: 필드 이름, 문자열·정수·불리언·열거형, 기본값, 필수 여부, 허용 값·범위, 헤더·본문·페이로드 구분.
- 상태: 초기 상태, 일반 상태와 종료 상태를 참여자별로 정의한다.
- 변수: 순서 번호, 재시도 횟수, 대기 중인 전송 내용 등을 참여자별로 보관한다.
- 규칙: 현재 상태 + 이벤트 + 조건 → 동작 + 다음 상태.
- 이벤트: 시나리오 입력, 하위 데이터 수신, 완전한 메시지 수신, 타이머 만료, 연결 종료·실패.
- 동작: 하위로 전송, 변수 갱신, 타이머 시작·취소, 상위로 전달, 상태 변경, 참여자 종료.

편집은 필드 표와 규칙 폼을 사용한다. 사용자 JavaScript 실행은 제공하지 않는다. 메시지 필드 참조, 비교, 복사, 제한된 정수 증감 등의 표현을 선언형으로 정의한다. 조건 충돌·잘못된 참조·타입 불일치는 해당 편집 위치로 연결한다.

사용자 정의 응용 프로토콜은 JSON Lines 기반 스트림 또는 한 데이터그램당 하나의 JSON 메시지를 지원한다. 전송 프로토콜은 구조화된 논리 패킷을 사용한다. 패킷 필드는 개념 모델이며 실제 TCP wire bytes나 임의의 바이너리 인코딩을 의미하지 않는다. 기존 HTTP 예제는 전용 텍스트 코덱을 사용한다.

### V1-004: 예제와 정확성 표시

| 예제 | 목적 | 지원 경계 |
| --- | --- | --- |
| HTTP/1.1 | 요청·응답 구조, 헤더·본문, 분할 수신과 응답 대기 | GET·POST의 제한된 요청·응답, 명시적인 본문 길이. 전체 표준 구현 아님 |
| TCP 연결 수립 | SYN·SYN-ACK·ACK, 주요 필드와 양쪽 상태 | 정상적인 능동·수동 연결 수립 개념 모델. 전체 TCP 구현 아님 |
| Ping/Pong | 사용자 정의 메시지와 응답 규칙 | 응용 계층, 스트림과 데이터그램용 호환 변형 |
| 단순 ACK·재전송 | 타이머·재전송·중복 제거 | 한 번에 하나를 전송하는 사용자 정의 전송 프로토콜. TCP로 표시하지 않음 |

예제별 기준 자료, 지원 항목, 생략 항목과 가정을 항상 열람할 수 있게 한다. 원본 예제는 보존하고 편집하려면 사용자 사본을 만든다. 사본은 사용자 정의 모델로 표시하고 원본 출처와 버전을 남긴다.

### V1-005: 실행·관찰·재현

실행, 일시정지, 한 단계 실행, 초기화, 이벤트 기록 재생을 제공한다. 실행 중의 실제 프로토콜 상태와 과거 기록을 선택한 재생 위치를 구분한다. 가상 시간을 사용하며 동일한 정의·환경·시나리오·seed·엔진 버전에서는 동일한 의미적 이벤트 기록을 생성한다.

시퀀스에는 프로토콜 이벤트와 환경 이벤트를 구분해 표시한다. 선택 시 데이터, 적용된 규칙, 상태·변수의 전후 값, 타이머, 원인 이벤트와 하위 전달 결과를 확인한다. 전송·수신·해석·상위 처리 완료를 구분한다. ACK 수신을 응용 처리 완료로 표시하지 않는다.

### V1-006: 검증과 종료

| 분류 | 사용자에게 보여줄 내용 |
| --- | --- |
| 정의 오류 | 서비스 불일치, 없는 상태·필드 참조, 타입 오류, 충돌하는 규칙 |
| 실행 진단 | 처리 규칙 없음, 타이머 만료, 연결 실패, 파싱 실패와 발생 위치 |
| 기대 조건 | 최종 상태, 전달 데이터·횟수, 순서, 정해진 시간 안의 완료 여부 |

실행 상태와 기대 조건의 통과·실패·미판정을 별도로 관리한다. 시간 초과를 기대하는 시나리오는 실제 시간 초과가 발생하면 기대 조건이 통과할 수 있다. 자원 제한이나 수동 중단으로 관찰이 끝나지 않았으면 통과로 표시하지 않는다. 중복 없음 같은 조건은 정한 관찰 기간 전체를 기준으로 판정한다.

검증 통과는 해당 모델과 실행 시나리오의 조건을 충족했다는 뜻이다. 전체 프로토콜의 정합성 증명, 실제 네트워크 호환성이나 성능 보장이 아니다.

### V1-007: 저장과 버전

정의·실험·시나리오는 로컬에 자동 저장하고 버전이 있는 파일로 내보내기·불러오기를 제공한다. 아직 유효하지 않은 편집 초안도 저장할 수 있으나 실행은 막는다. 각 실행은 시작 시점의 정의·환경·시나리오·seed·엔진 버전을 별도 보관한다. 편집 후에는 이전 실행 결과가 현재 정의와 다른 버전임을 표시한다.

저장 실패 시 미저장 상태와 재시도·내보내기 수단을 제공한다. 손상되거나 지원하지 않는 버전의 가져오기는 기존 데이터를 변경하지 않는다. 계정·서버 저장·동기화는 없다.

## 화면 구성

시작 화면은 예제, 내 실험, 새 실험 만들기로 구성한다. 새 실험은 대상 계층 → 프로토콜·하위 서비스 → 기본 시나리오 순서로 안내한다.

| 작업 공간 보기 | 중앙 내용 | 오른쪽 선택 항목 |
| --- | --- | --- |
| 실험 구성 | 계층, 참여자 A·B, 프로토콜과 하위 서비스 연결 | 서비스 요구사항, 보장사항과 호환성 오류 |
| 프로토콜 | 메시지·패킷 필드 표, 상태·변수 목록, 규칙 폼 | 선택한 필드·상태·규칙의 속성 편집 |
| 통신 환경 | 방향별 지연·손실·중복, 청크·연결 조건, seed | 설정 설명, 단위와 범위, 재현할 장애 |
| 시나리오·검증 | 최초 입력, 입력 시각, 관찰 기간, 기대 조건 | 입력 값 또는 조건 편집 |
| 실행 | 시퀀스, 가상 시간, 양쪽 상태, 실행 제어 | 선택 이벤트의 원인·규칙·값·상태 변화 |

상단은 실험 이름·원본/사본·저장 상태를 표시한다. 왼쪽은 보기와 구성 목록, 하단은 이벤트·진단·기대 조건 결과다. 같은 항목은 보기 간 선택을 연결한다. 오류를 선택하면 원인이 있는 편집 위치 또는 실행 이벤트로 이동한다. 목록과 규칙은 키보드로 선택·편집할 수 있고 색만으로 상태를 구별하지 않는다.

실행 중 편집은 일시정지 또는 실행 종료 후 새 초안에 반영하며 현재 실행 snapshot을 변경하지 않는다. 좁은 화면에서는 패널을 쌓거나 상세 패널을 전환하며 필수 작업이 가려지지 않게 한다.

## 범위 밖

실제 서버·기기 연결, 패킷 캡처, 전체 TCP/HTTP 구현, HTTPS·TLS, HTTP/2·3, 임의 바이너리 코덱, IP·링크·물리 계층 모델, 라우팅·다중 참여자, 여러 사용자 계층의 연결 실행, 성능 벤치마크, 계정·협업·클라우드 동기화는 후속 범위다. 범위 밖 항목을 자동으로 기술 부채로 등록하지 않는다.

| 항목 | 상태 | 결정 시점·근거 |
| --- | --- | --- |
| 제품 목적, 응용·전송 계층, 두 참여자와 가상 환경 | Resolved | 2026-10-30 사용자와 합의 |
