# 계층별 프로토콜 설계·이해·검증 도구 v1

상태: Accepted
합의일: 2026-10-30
구현 상태: P5 폼·실행·장애 환경, 제한된 HTTP/1.1·TCP 연결 예제와 출처·버전·사용자 사본까지 연결했다. P6에서 invalid draft·실험 사본·snapshot/결과의 IndexedDB 자동 저장, 파일 왕복과 과거 기록 탐색/명시적 snapshot 재실행을 구현했다. P7의 브라우저·키보드·응답성/CI 검증까지 완료했으며 실제 완료 기록은 단계별 계획을 따른다.

## 목적과 사용자

기존 프로토콜의 구조와 통신 흐름을 살펴보고, 자기 프로토콜을 정의하거나 기존 예제의 사본을 수정해 가상 참여자 사이에서 검증하는 도구다. 주요 사용자는 프로토콜을 이해하거나 설계하려는 개발자와 학습자다. 기존 프로토콜의 정확한 지원 범위를 표시하고, 실행 결과를 해당 규칙·환경·시나리오에 연결한다.

첫 버전은 데스크톱 웹 작업 공간을 기준으로 설계한다. 제품 목적과 기능 범위는 사용자와 합의했으며, 도구와 기초 계약은 [P0 확정 계약](../design-docs/p0-execution-contract.md)에 기록했다.

## 사용자 행동

1. 예제 또는 내 실험을 열거나 새 실험을 만든다.
2. 응용 계층 또는 전송 계층을 선택한다.
3. 양쪽 참여자의 프로토콜과 호환되는 하위 통신 서비스를 선택한다.
4. 메시지·패킷 형식, 상태·변수, 통신 규칙을 편집한다.
5. 하위 환경의 지연·손실 등 조건과 실행 시나리오·기대 조건을 정한다.
6. 전체 실행 또는 단계 실행으로 통신을 관찰한다.
7. 이벤트를 선택해 데이터, 적용 규칙, 환경의 처리와 상태 변화를 확인한다.
8. 환경을 바꿔 다시 실행하거나 실험을 저장·내보내 다른 세션에서 재개한다.

## 제품 정책과 예외

### V1-001: 실험 단위와 계층

하나의 실험은 프로토콜 정의, 하위 환경, 시나리오, 기대 조건으로 구성한다. 참여자는 A와 B 두 개이며 각자의 상태와 변수를 소유한다. 동일한 정의를 양쪽에서 재사용해도 실행 상태는 공유하지 않는다.

응용·전송 두 계층의 프로토콜을 각각 정의할 수 있고 한 번의 실행은 한 계층을 대상으로 한다. 하위 계층은 서비스 모델로 제공한다. 여러 사용자 정의 계층의 연결 실행은 후속 범위다. 계층 이름과 요청·응답 같은 통신 패턴은 별개의 속성이다. 응용 계층 프로토콜도 데이터그램을 사용할 수 있다.

### V1-002: 하위 서비스와 호환성

| 하위 서비스 | 보장 | 설정 가능한 조건 |
| --- | --- | --- |
| 바이트 스트림 | 연결이 유지되는 동안 바이트의 순서와 중복 없는 전달. 메시지 경계는 보존하지 않음 | 방향별 전달 지연, 읽기 청크 크기·합치기, 정상 종료·연결 실패 시점 |
| 데이터그램 | 전달된 패킷의 경계 보존. 전달 성공·순서는 보장하지 않음 | 방향별 지연·지연 변동, 손실률, 중복률, 특정 전송 패킷 손실 |

프로토콜이 요구하는 서비스와 환경이 제공하는 서비스가 다르면 실행 전에 오류를 표시한다. 스트림에 임의의 바이트 손실·중복·순서 역전을 적용하지 않는다. 연결 실패는 명시적인 종료·오류로 전달한다. 데이터그램의 순서 역전은 전달 지연 차이로 재현한다.

대역폭, 혼잡, MTU, 체크섬 오류와 비트 손상은 첫 버전의 환경 설정에 포함하지 않는다. 환경의 전달 지연과 참여자의 처리·응답 대기 시간은 별도 항목으로 표시한다.

### V1-003: 프로토콜 정의와 편집

- 형식: 필드 이름, 문자열·정수·불리언·열거형, 기본값, 필수 여부, 허용 값·범위, 헤더·본문·페이로드 구분.
- 상태: 초기 상태, 일반 상태와 종료 상태를 참여자별로 정의한다.
- 변수: 순서 번호, 재시도 횟수, 대기 중인 전송 내용 등을 참여자별로 보관한다.
- 규칙: 현재 상태 + 이벤트 + 조건 → 동작 + 다음 상태.
- 이벤트: 시나리오 입력, 하위 데이터 수신, 완전한 메시지 수신, 타이머 만료, 연결 종료·실패.
- 동작: 하위로 전송, 변수 갱신, 타이머 시작·취소, 상위로 전달, 상태 변경, 참여자 종료.

편집은 필드 표와 규칙 폼을 사용한다. 사용자 JavaScript 실행은 제공하지 않는다. 메시지 필드 참조, 비교, 복사, 제한된 정수 증감 등의 표현을 선언형으로 정의한다. 조건 충돌·잘못된 참조·타입 불일치는 해당 편집 위치로 연결한다.

사용자 정의 응용 프로토콜은 JSON Lines 기반 스트림 또는 한 데이터그램당 하나의 JSON 메시지를 지원한다. 전송 프로토콜은 구조화된 논리 패킷을 사용한다. 패킷 필드는 개념 모델이며 실제 TCP wire bytes나 임의의 바이너리 인코딩을 의미하지 않는다. 기존 HTTP 예제는 전용 텍스트 코덱을 사용한다.

### V1-004: 예제와 정확성 표시

| 예제 | 목적 | 지원 경계 |
| --- | --- | --- |
| HTTP/1.1 | 요청·응답 구조, 헤더·본문, 분할 수신과 응답 대기 | GET·POST의 제한된 요청·응답, 명시적인 본문 길이. 전체 표준 구현 아님 |
| TCP 연결 수립 | SYN·SYN-ACK·ACK, 주요 필드와 양쪽 상태 | 정상적인 능동·수동 연결 수립 개념 모델. 전체 TCP 구현 아님 |
| Ping/Pong | 사용자 정의 메시지와 응답 규칙 | 응용 계층, 스트림과 데이터그램용 호환 변형 |
| 단순 ACK·재전송 | 타이머·재전송·중복 제거 | 한 번에 하나를 전송하는 사용자 정의 전송 프로토콜. TCP로 표시하지 않음 |

예제별 기준 자료, 지원 항목, 생략 항목과 가정을 항상 열람할 수 있게 한다. 원본 예제는 보존하고 편집하려면 사용자 사본을 만든다. 사본은 사용자 정의 모델로 표시하고 원본 출처와 버전을 남긴다.

### V1-005: 실행·관찰·재현

실행, 일시정지, 한 단계 실행, 초기화, 이벤트 기록 재생을 제공한다. 실행 중의 실제 프로토콜 상태와 과거 기록을 선택한 재생 위치를 구분한다. 가상 시간을 사용하며 동일한 정의·환경·시나리오·seed·엔진 버전에서는 동일한 의미적 이벤트 기록을 생성한다.

시퀀스에는 프로토콜 이벤트와 환경 이벤트를 구분해 표시한다. 선택 시 데이터, 적용된 규칙, 상태·변수의 전후 값, 타이머, 원인 이벤트와 하위 전달 결과를 확인한다. 전송·수신·해석·상위 처리 완료를 구분한다. ACK 수신을 응용 처리 완료로 표시하지 않는다.

### V1-006: 검증과 종료

| 분류 | 사용자에게 보여줄 내용 |
| --- | --- |
| 정의 오류 | 서비스 불일치, 없는 상태·필드 참조, 타입 오류, 충돌하는 규칙 |
| 실행 진단 | 처리 규칙 없음, 타이머 만료, 연결 실패, 파싱 실패와 발생 위치 |
| 기대 조건 | 최종 상태, 전달 데이터·횟수, 순서, 정해진 시간 안의 완료 여부 |

실행 상태와 기대 조건의 통과·실패·미판정을 별도로 관리한다. 시간 초과를 기대하는 시나리오는 실제 시간 초과가 발생하면 기대 조건이 통과할 수 있다. 자원 제한이나 수동 중단으로 관찰이 끝나지 않았으면 통과로 표시하지 않는다. 중복 없음 같은 조건은 정한 관찰 기간 전체를 기준으로 판정한다.

검증 통과는 해당 모델과 실행 시나리오의 조건을 충족했다는 뜻이다. 전체 프로토콜의 정합성 증명, 실제 네트워크 호환성이나 성능 보장이 아니다.

### V1-007: 저장과 버전

정의·실험·시나리오는 로컬에 자동 저장하고 버전이 있는 파일로 내보내기·불러오기를 제공한다. 아직 유효하지 않은 편집 초안도 저장할 수 있으나 실행은 막는다. 각 실행은 시작 시점의 정의·환경·시나리오·seed·엔진 버전을 별도 보관한다. 편집 후에는 이전 실행 결과가 현재 정의와 다른 버전임을 표시한다.

저장 실패 시 미저장 상태와 재시도·내보내기 수단을 제공한다. 손상되거나 지원하지 않는 버전의 가져오기는 기존 데이터를 변경하지 않는다. 계정·서버 저장·동기화는 없다. 원자적 저장·탭 충돌·브라우저 보존 한계와 파일·재생 세부 계약은 [P6 문서](../design-docs/p6-persistence-replay.md)를 따른다.

### V1-008: 프로토콜 상태도

상태와 규칙에서 상태도를 자동 생성한다. 초기/종료·현재 참여자의 상태, 표시 위치까지 최근 적용된 전이를 문구와 모양으로 구분한다. 같은 출발/도착의 규칙은 한 화살표에 묶되 각 규칙을 선택해 이벤트·조건·동작을 확인할 수 있다. 화살표는 정의된 가능 전이이며 조건 충족이나 실제 실행의 증명이 아니다.

프로토콜 보기의 그림은 현재 초안을 따른다. 실행 보기에서 ‘실행 상태도 보기’를 열면 A/B 각각의 실행 당시 정의를 본다. 과거 기록의 cursor 이후 규칙은 강조하지 않는다. snapshot과 현재 초안의 정의 내용/ID/revision이 모두 같을 때에만 편집 위치로 이동하며, 다른 경우 저장된 설정을 새 초안으로 복원하도록 안내한다.

상태 40개·규칙 20개씩 페이지를 나누고 초기/현재 상태와 표시한 규칙의 양 끝을 추가 표시한다. 없는/중복/빈 상태 참조는 오류 노드로 표시하며 임의로 연결하지 않는다. 키보드 Enter/Space 선택·native 스크롤·75/100/125% 크기·현재 위치 따라가기를 제공한다. 긴 값은 요약하고 전체 정의는 기존 폼에 남긴다. 시퀀스 그림과 연동은 V1-009/010, 초안의 시각적 작성은 V1-011을 따른다.

### V1-009: 통신 시퀀스 다이어그램

실행 보기의 ‘통신 시퀀스 보기’를 열면 실행 snapshot의 A/B lifeline과 관찰 기록을 그린다. 행 간격은 고정이며 가상 시각·sequence 순서를 함께 표시한다. 송신은 중앙까지의 반쪽 화살표, 실제 하위 수신은 상대 참여자까지의 전체 화살표, 명시적 데이터그램 손실/스트림 연결 차단은 ×, 내부 이벤트는 꺾인 선으로 구분한다. 송신의 수신 미관찰은 손실 판정이 아니다. 환경의 도착 예정은 실제 수신으로 표시하지 않는다.

바이트 청크 수신·해석·상위 전달을 구분하고 합쳐 읽기의 모든 원인 송신과 직접 후속 이벤트를 탐색한다. 실제 복사본 metadata로 원본/중복 도착을 구분한다. 범용 trace는 재전송 의도를 기록하지 않으므로 타이머 만료를 원인으로 같은 참여자가 같은 메시지 ID·값을 반복 송신했을 때만 ‘재전송 후보’로 추정한다. 그 외 같은 값 반복은 반복 송신으로 표시한다. 타이머 만료가 관찰된 실패 전이의 원인이어야 ‘타임아웃 실패’로 표시한다.

선택한 행에서 메시지 필드 ID·wire 이름·값, 바이트와 원인/직접 후속을 확인한다. 아직 해석되지 않은 청크에 원인 송신 필드를 보여줄 때는 수신 해석 결과가 아님을 명시한다. 현재 초안의 필드로 과거 데이터를 설명하지 않으며 snapshot과 초안이 달라진 경우 규칙 편집 이동을 막는다. 기록 cursor 뒤의 수신·해석·실패를 미리 표시하지 않는다.

기본 통신·장애 보기와 전체 이벤트 보기, 30행 페이지·처음/이전/다음/현재 끝, native 가로/세로 스크롤·Enter/Space 선택·선택 상세 이동을 제공한다. 관계는 20개씩, 메시지는 32필드·값 240자, 수신의 해석 결과는 4개를 미리 보여주며 나머지는 관계 탐색/원본 bundle로 확인한다. 전체 기록·저장 형식·엔진 동작은 바꾸지 않는다. 상태도 연동은 V1-010을 따르며 직접 그래프 편집은 후속 범위다.

### V1-010: 상태도와 시퀀스 연동

실행 snapshot의 두 그림은 같은 이벤트 선택과 관찰 prefix를 공유한다. 시퀀스/기록에서 이벤트를 고르면 해당 참여자의 규칙과 실제 연결된 실행 회차를 표시한다. 한 회차가 확정되면 관찰된 transition의 ‘선택 전/후’ 상태·변수를 보여주고, cursor 기준 ‘현재 A/B’와 구분한다. ruleId가 있는 동작이라도 transition이 아직 없으면 규칙만 선택하고 상태 commit을 추정하지 않는다. 하나의 청크가 여러 parsed/transition으로 이어지면 회차 목록에서 고르기 전까지 한 전이로 확정하지 않는다.

회차는 같은 참여자·규칙·직접 trigger로 구분한다. 송신·상위 전달·타이머 동작과 transition을 연결하고, parsed의 직접 원인 receive를 포함한다. 환경 장애는 원인 송신의 회차에 연결하며 상대 참여자의 전이를 추정하지 않는다. 직접 원인이 없는 기록을 규칙 ID만으로 묶지 않는다. 명시적 무시도 실제 자기 전이 회차로 구분한다.

실행 상태도의 규칙/상태를 고르면 현재 prefix에서 해당 규칙의 실행 또는 상태의 진입/이탈 회차를 조회하고 최근 회차를 선택한다. 시퀀스는 관련 행과 선택 회차를 구분해 표시한다. 연결된 실행이 없으면 이전 강조/상세를 지우고 정의만 보여준다. 회차 목록은 20개씩 탐색하고 회차를 선택해 전후 값·해당 이벤트로 이동한다. history 회차 선택은 해당 위치로 cursor를 옮기므로 이후 회차를 보려면 저장 시점 등으로 관찰 범위를 늘린다.

선택은 live 실행과 기록 자동 재생을 일시정지한다. 기록 자동 재생 중에는 cursor·선택 이벤트·참여자·두 그림이 함께 이동한다. 명시적인 ‘연결된 상태도 보기’/‘시퀀스에서 관련 기록 보기’ 버튼은 상대 패널을 펼치고 summary에 초점을 옮기며, 일반 선택은 페이지 전체를 자동 스크롤하지 않는다. 필요한 규칙/상태·시퀀스 페이지를 맞추고 같은 참여자의 선택 변경에서는 확대율을 유지한다. 상태도에서 시퀀스로 이동하면 ‘연결된 기록만 보기’를 켜서 회차의 흐름을 모아 보며, 해제하면 전체 흐름으로 돌아간다. 다른 실행/기록·초기화·현재 위치 따라가기에서는 오래된 선택을 보존하지 않는다. 초안 상태도의 직접 편집·엔진/저장 schema 변경은 포함하지 않는다.

### V1-011: 초안 상태도의 시각적 작성

프로토콜 보기에서 ‘그림에 상태 추가’로 새 상태를 만들고 옆 편집기에서 ID·이름·종료 여부를 수정한다. 생성 ID는 기존 상태뿐 아니라 초기/전이의 미해결 상태 참조도 피해서 정한다. 상태를 추가해 기존 잘못된 참조를 우연히 복구하지 않는다. 생성/수정은 기존 초안 edit 경로로 revision·정확히 일치하는 A/B 참조·미완성 JSON·자동 저장을 관리하고, 실행 snapshot은 유지한다.

‘전이 연결 시작’ 후 출발·도착 노드를 순서대로 선택하거나 해당 dropdown에서 고른다. 같은 상태를 다시 고르면 자기 전이가 된다. 발생 이벤트(시나리오 입력·메시지 수신·타이머·스트림 연결 종료/실패)와 참조를 선택해야 생성할 수 있다. 빈/중복 ID·없는 상태·오래된 index/ID·없는/중복 메시지/타이머와 데이터그램의 연결 이벤트는 거부한다. 연결 중 정의 revision/ID가 바뀌면 선택을 무효화하고 다시 시작한다. Escape/취소는 초안을 바꾸지 않는다.

새 규칙은 임의의 send·finish·타이머 동작을 넣지 않은 상태 이동이다. 동작 없는 자기 전이는 생성 전에 명시적 무시 의미를 안내하고 ignore=true로 만든다. 같은 출발 상태/이벤트의 기존 규칙은 충돌 가능성을 안내하되 조건부 평행 규칙을 작성할 수 있도록 초안 생성을 허용한다. 기존 validator의 충돌 진단이 사라지기 전에는 실행할 수 없다. 새 규칙을 선택한 옆 편집기에서 이벤트·조건·동작을 수정한다.

선택 상태/규칙의 기존 폼은 전체 목록과 옆 편집기 중 한 곳에만 표시해 JSON Pointer가 중복되지 않게 한다. 옆 편집기는 해당 항목의 진단을 보여주고 ‘전체 목록에서 편집’으로 돌아갈 수 있다. 이름·조건을 편집해도 그림의 선택·확대율을 유지하며, 새 항목이 다른 페이지에 있으면 해당 페이지를 연다. 상태/규칙 배열의 구조 변경·정의 전환 시 옆 편집 대상은 초기화한다. 연결 출발/도착은 문구와 모양으로 구분하고 페이지 밖 endpoint도 함께 표시한다. Enter/Space로 노드를 고르고 좁은 화면에서는 옆 편집기가 아래로 쌓인다. 실행/과거 그림의 직접 추가·연결, 자유 배치/드래그·삭제 참조의 자동 재작성은 포함하지 않는다.

### V1-012: 반복 실험과 결과 비교

‘반복 실험’ 보기에서 묶음 이름, seed 목록, 지연 ms 목록, 데이터그램 손실률 % 목록과 적용 방향(양방향/A→B/B→A)을 설정한다. 지연·손실의 모든 조합에 같은 seed 목록을 사용하며 seed 개수가 조건별 반복 횟수다. 빈 지연·손실 목록은 해당 방향의 초안 값을 유지한다. 다른 방향과 지연 변동·중복·특정 전송 손실·연결·청크 설정은 보존한다. 스트림에는 손실률 입력을 제공하지 않는다. 중복 seed/조건, 잘못된 범위·불완전 JSON·정의 오류를 거부하고 조건 수×반복 횟수를 실행 전에 표시한다. 작성 중인 조건 입력은 같은 초안에서 화면을 오가도 유지한다. 새로고침 후에는 저장된 결과에서 실제 조건을 확인한다.

시작 시 프로토콜·시나리오·환경을 고정한다. 조건별 실행은 독립 엔진·난수 상태를 사용하며 초안과 단일 실행 snapshot을 변경하지 않는다. 기존 단일 실행을 일시정지하고 반복 실행을 시작한다. 실행당 64개 queue 작업마다 브라우저에 제어를 돌려주며 진행·중단을 제공한다. 단일 실행 시작·기록 선택·초안 교체·bundle 가져오기 시 반복 실행을 중단한다. 중단 시 시작한 실행을 cancelled 기록으로 보존하고 대기 실행은 생성하지 않는다. 메모리 기록은 기존 자동 저장을 따르며 ‘브라우저에 저장됨’ 이후 다시 열면 결과를 복원한다. 새로고침 후 자동 재개하지 않는다.

각 실행은 기존 SavedRun에 선택적 묶음 metadata를 붙여 로컬 저장·bundle에 보존한다. 이전 기록은 변경 없이 읽는다. 한 묶음 최대 100회와 작업 공간의 남은 기록 수·64 MiB 한도를 지키며 자동 삭제하지 않는다. 실행 중 용량이 부족해진 경우 해당 실행을 추가하지 않고 기존 결과와 오류를 표시한다. 저장 transaction 실패·탭 충돌은 기존 저장 상태·복구 정책을 따른다. 가져오기에서 묶음 ID 충돌은 전체 묶음을 별도 ID로 분리한다. 새 metadata가 있는 bundle을 이전 앱은 거부할 수 있다.

현재 실험의 최대 두 묶음을 선택해 수정 전후 또는 환경 조건을 비교한다. 각 조건은 기대 조건 통과/실패/미판정의 실행 수, 통과율, 미실행·삭제 수, 가상 완료 시간의 평균·표본 수, 송신·타이머 만료 평균을 표시한다. 통과는 completed이면서 모든 기대 조건이 pass인 경우다. completed만으로 통과하지 않으며 취소·한도·오류·미완료 관찰은 미판정이다. 통과율 분모는 저장된 실행 전체이며 미실행·삭제는 분리한다. 가상 완료 시간은 통과 실행의 성공 종료 참여자 중 가장 늦은 finishedAt이며 계속 대기하는 참여자는 제외한다. 종료 참여자가 없으면 시간을 표시하지 않는다. timeout을 기대하는 검증의 통과는 프로토콜 성공 종료를 의미하지 않는다. 재전송 의도는 단정하지 않고 실제 송신·타이머 만료를 센다.

조건 집계는 20행씩 탐색하고 가로 스크롤·키보드·390px 화면을 제공한다. 조건의 실행 목록은 seed·판정·엔진 상태와 기존 기록 재생으로 연결한다. 과거 기록의 상태도·시퀀스·cursor 계약은 유지한다. 표본 통과율은 선택한 모델/환경/seed의 관찰 결과이며 전체 정합성이나 실제 네트워크 성능을 나타내지 않는다.

### V1-013: 규칙 선택과 변수 변경 설명

실행 보기의 ‘실행 이유 설명’을 열면 이벤트 기록·시퀀스·상태도와 공유하는 선택 회차를 설명한다. 설명은 현재 관찰 prefix 안의 실제 transition, 같은 참여자의 직접 trigger와 frozen snapshot만 사용한다. 출발 상태와 입력/해석된 메시지 수신·타이머 만료·연결 이벤트가 맞는 후보를 찾고, 후보별 조건의 참/거짓·각 비교 피연산자 값과 AND/OR/NOT의 계산을 보여준다. AND의 거짓 이후·OR의 참 이후 분기는 ‘평가 생략’으로 표시하고 값을 계산하지 않는다. 조건 없는 규칙도 상태·이벤트 일치를 표시한다. 다른 상태/이벤트의 규칙은 해당 발생 이벤트의 후보로 표시하지 않는다.

규칙의 assign을 원래 action 번호 순서대로 재구성한다. 대상 변수의 대입 전 값, 식에서 실제 읽는 필드·변수 값, 산술과 대입 결과를 표시하며 뒤 assign은 앞 assign이 바꾼 임시 변수를 읽는다. 같은 변수의 반복 대입·같은 값 대입을 보존하고 최종 값이 바뀐 변수는 기록된 전후 값·관련 action 번호를 연결한다. 후보 조건은 모든 대입보다 앞선 before 값으로 평가한다. 현재 참여자 값이나 수정한 초안으로 과거 회차를 설명하지 않는다.

중간 계산은 저장한 snapshot·before/trigger에서 복원한 값임을 표시한다. 엔진의 값/비교 평가 함수를 재사용하며 유일한 일치 규칙·nextState/ignore·최종 변수 전체를 실제 transition과 대조한 경우에만 ‘기록과 일치’를 표시한다. 값/규칙 불일치·평가 오류는 ‘기록 불일치’, 지원하지 않는 snapshot 버전·직접 trigger 부족은 ‘설명 불가’, 연산/값 크기 상한은 ‘일부 설명’으로 구분한다. 이 상태들은 프로토콜 기대 조건 통과 판정과 별개다. 설명 불일치의 계산을 실제 적용 완료로 해석하지 않는다.

합쳐 읽기의 여러 parsed/transition이나 같은 규칙의 여러 회차는 하나로 추정하지 않고 회차를 고르게 한다. cursor 뒤의 transition은 설명하지 않는다. 송신만 보이거나 오류/자원 한도로 commit 기록이 없으면 assign 적용 완료를 주장하지 않는다. 동적 오류로 rollback한 규칙은 실제 transition이 없으므로 실행 완료 설명을 제공하지 않는다. 기존 원본 이벤트·상태도 회차로 확인할 수 있다.

설명은 패널을 열었을 때만 계산한다. 계산은 1024 operation·4096 value node·누적 32768 value character·깊이 32로 제한한다. 원본 wire bytes를 복사하거나 전체 stringify하지 않는다. 후보·조건·대입·변수 변경과 다중 회차는 20개씩 탐색하고 표시하는 긴 값·이름은 요약한다. 키보드·390px 배치, 과거 기록 복원과 반복 실험의 개별 실행 재생에서도 같은 기능을 제공한다. 저장/엔진/trace 버전과 실행 결과는 바꾸지 않으며 기존 기록도 재실행 없이 설명한다.

### V1-014: 시나리오 묶음과 회귀 검증

‘시나리오 묶음’에서 초안당 하나의 묶음·최대 20사례를 만든다. 현재 입력·기대 조건·환경·seed를 캡처하거나 사례를 복제하고 이름·활성 여부·설정을 편집/삭제한다. 프로토콜 정의·참여자 참조는 현재 공통 초안을 공유한다. 사례 수정은 기본 시나리오나 다른 사례를 바꾸지 않으며 사례 revision과 공통 초안 version을 구분한다. 서비스가 달라지면 호환 오류를 표시하고 현재 초안의 환경을 사례에 적용할 수 있다.

기존 시나리오·환경 폼을 선택 사례의 EditorContext로 재사용한다. 공통 정의의 미완성 JSON과 활성 사례의 오류는 전체 실행을 막고 비활성 사례의 오류는 보존한다. 편집 가능한 invalid 사례·마지막 유효 값·미완성 raw 텍스트는 저장하며 보관한 JSON을 확인하고 명시적으로 마지막 유효 값으로 되돌릴 수 있다. 깨진 구조·잘못된 raw 경로·ID 중복·한도 초과는 가져오기 전에 거부한다.

전체 검증 시작 시 공통 프로토콜과 활성 사례 목록을 고정하고 사례마다 새 엔진·난수·타이머·상태로 실행한다. 반복 실험과 회귀 검증은 하나의 scheduler로 동시에 하나만 실행한다. 64개 queue 작업마다 제어를 양보하고 중단 시 진행 중인 사례만 cancelled로 보존한다. 사례 사이에 중단하면 취소 기록 없이 대기 사례를 미실행으로 남긴다. 단일 실행·기록 선택·초안 교체/가져오기는 실행 묶음을 중단한다. completed와 기대 조건 통과는 구분하며 기대한 timeout도 기대 조건이 맞으면 통과할 수 있다.

사례 ID/이름 manifest와 suite ID/revision·실행 그룹을 snapshot과 보존한다. 두 실행의 같은 묶음/사례와 동일한 scenario(기대 조건 포함)·environment·seed·엔진/난수/limits일 때만 통과→실패를 ‘새 실패’, 실패→통과를 ‘개선’, 같은 전체 판정을 ‘동일 판정’으로 표시한다. 조건 변경·엔진 차이·다른 묶음·미판정·미실행·비교 대상 없음은 별도로 표시한다. manifest에 있지만 기록이 없으면 미실행·삭제, 실행 대상 자체에 없으면 대상 없음이다. 판정 비교는 전체 이벤트의 동등성을 뜻하지 않는다. 실패/미판정 필터·20행 페이지·키보드·390px/native 표 스크롤을 제공하고 사례별 현재/기준 기록을 기존 상태도·시퀀스·실행 이유 설명에서 재생한다.

DraftRecord.suite와 SavedRun.regression은 optional 확장으로 이전 workspace를 계속 읽는다. 새 필드가 있는 bundle은 이전 앱에서 거부될 수 있다. 가져오기/복구 충돌은 부모·suite·실행 그룹 ID를 함께 분리하고 기존 데이터를 덮어쓰지 않는다. 사례/묶음/초안 삭제 후에도 과거 snapshot을 유지한다. 전체 기록 100개·64 MiB, 저장 실패/재시도·‘저장됨’ 이후 복원과 자동 재개 없음 정책을 유지한다. 신규 dependency·엔진/trace 버전 변경·실제 네트워크는 포함하지 않는다.

### V1-015: 실패 원인 진단과 관련 기록 이동

실행의 ‘기대 조건 진단’ 또는 ‘실패 진단과 관련 기록’에서 실행 당시 기대 조건을 선택한다. 상태는 기대 상태/현재 관찰 상태, 전달 횟수는 메시지별 상위 deliver 횟수, 전달 값은 당시 정의의 기본값을 반영한 기대 메시지/일치 수와 첫 관찰 값, 완료 기한은 성공 완료 요구/실제 outcome·최초 종료 시각을 비교한다. 같은 메시지의 다른 관찰 값은 개별 근거에서 기존 이벤트 상세로 확인한다. 초기 상태만 관찰되면 당시 snapshot이 근거이며 없는 전이를 생성하지 않는다.

완료한 관찰의 재구성 판정·최종 상태/outcome·최초 종료 시각을 저장 판정/참여자와 대조해 ‘판정과 일치’를 표시한다. 판정 일치는 근본 원인의 유일성이나 전체 기록의 완전성을 증명하지 않는다. 취소·진행/재생 중·한도·참여자 오류는 미판정과 현재까지의 관찰로 표시한다. 지원하지 않는 버전/없는 조건·계산 한도·기록 모순은 각각 진단 불가·일부 진단·기록 불일치로 구분하며 기존 판정을 변경하지 않는다. 과거 cursor 밖의 이벤트·최종 상태·판정은 근거에 포함하지 않는다. 공통 초안의 수정은 저장된 사례 진단에 영향을 주지 않는다.

판정 근거는 해당 참여자의 최근 전이·메시지별 상위 전달·종료 전이이며, 참고 관찰은 같은 실행의 환경 이벤트와 해당 참여자의 타이머 만료·연결/오류·최근 전이다. 참고 관찰을 단일 확정 원인 사슬로 표시하지 않는다. ‘연결 근거’는 실제 causeEventId·합쳐 읽기의 sourceEventIds와 같은 참여자/타이머/세대의 start를 따라가며 현재 prefix 안의 앞선 기록만 허용한다. 타이머와 손실 사이의 직접 연결이 없는 경우 그 인과관계를 추정하지 않는다. 없는/잘못된 참조와 유한 탐색 상한을 표시한다.

‘기록 보기’는 자동 진행/기록 재생을 멈추고 공유 선택·시퀀스 상세로 이동한다. 현재 구간에 하나의 실제 전이가 연결된 근거에만 ‘실행 설명 보기’를 제공하고, 그 전이를 선택해 V1-013을 연다. 상태도도 같은 선택을 사용한다. 과거 기록에서 이동하면 그 이벤트까지의 prefix로 좁혀지므로 최종 진단은 ‘저장 시점’에서 다시 확인한다. 단일 실행·과거 기록·반복 실험·회귀 사례 재생에 같은 동작을 제공한다.

패널을 열었을 때 선택 조건만 계산한다. 최대 10,000개 이벤트를 읽되 wire payload를 복사/해석하지 않는다. 값 비교는 누적 4096 node·32768 character·깊이 32, 연결 탐색은 최대 64개, 근거/참고/연결 기록은 페이지당 20개이며 긴 값/ID는 요약한다. 키보드·390px와 진단을 연 상태의 10k/1 MiB 응답성을 검증한다. 저장/engine/trace 버전·실행 결과·production dependency는 변경하지 않는다.

### V1-016: 메시지 구조 시각화

실행의 이벤트/시퀀스를 선택하고 ‘메시지 구조 보기’를 열면 당시 참여자 정의와 관찰된 전송 표현을 연결한다. 필드 카드에 stable ID·wire 이름·타입·필수/선택·논리 배치·기록 값을 표시하고, 전송 영역과 필드를 선택해 `[start,end)` byte 범위·길이와 실제 hex/ASCII 페이지를 강조한다. header/body/payload는 JSON 코덱에서 논리 분류이며 고정 크기 binary header를 만들어내지 않는다. 영역 카드의 화면 크기는 byte 길이 비율이 아니며 실제 길이는 숫자로 표시한다.

HTTP 송신은 관찰 bytes에서 시작 줄·각 헤더·CRLF 종료·현재 송신 끝까지의 본문을 표시한다. request method/target, response status/reason, 선언한 헤더 값과 본문 필드를 실제 범위로 연결한다. Content-Length는 코덱이 계산한 전송 헤더 값이며 현재 송신 본문 byte 수와 함께 표시하고 차이를 명시한다. 중복 헤더는 단일 필드 범위를 선택하지 않는다. raw HTTP는 구획 표시와 유효성 판정을 구분한다. 제한된 헤더 분석 구간에 경계가 없으면 본문을 추정하지 않는다. 전체 HTTP 검증이나 수신 성공을 새로 판정하지 않는다.

작은 완전한 JSON 송신은 실제 envelope·messageId·wire 필드 token·JSON Lines LF를 표시한다. 문자열의 따옴표/escape와 UTF-8 byte offset을 포함하며 0/false/빈 문자열을 보존한다. 중복 key·잘못된 UTF-8/JSON·단일 frame을 확인할 수 없는 경우 원시 bytes로 표시한다. 전송 값과 메시지 필드 기록이 다르면 명시한다. 큰 JSON의 token 분석은 생략하고 필드 값과 원시 byte 페이지를 별도로 제공한다. 논리 패킷은 실제 wire-name 필드를 표시하되 binary TCP/IP encoding이나 byte offset을 부여하지 않는다.

receive의 byte 청크는 현재 청크만 표시한다. 원인 송신/다른 청크/나중 parsed를 합쳐 완전한 메시지나 필드 범위를 추정하지 않는다. input/parsed/deliver에는 당시 필드 값을 표시하고 없는 wire를 재생성하지 않는다. 현재 history cursor 밖 이벤트는 조회하지 않으며 새 초안·복원/회귀 사례에서도 frozen snapshot과 실제 선택 기록을 사용한다. 지원하지 않는 버전/없는 정의는 원시 bytes와 명시적 제한을 제공한다. 이 조회는 재전송·재해석·실행 판정·기록 저장을 변경하지 않는다.

패널을 열었을 때만 계산한다. 구조 분석은 앞 32768 bytes, JSON token 1024개/깊이 8, 필드/영역 각 128개로 제한한다. 값은 240자, 필드/영역은 20개/page, 실제 byte 표는 256 bytes/page이며 처음/이전/다음/끝/페이지 번호/선택 범위로 이동할 수 있다. 큰 원본은 trace/bundle에 보존하고 전체 payload를 복사하지 않는다. 키보드·390px 내부 가로 스크롤과 열린 구조 패널의 10k/1 MiB 응답성 500ms·32768자 미만을 검증한다. 기존 입력·저장·프레임 한도, engine/trace/storage 버전과 dependency는 유지한다.

## 화면 구성

시작 화면은 예제, 내 실험, 새 실험 만들기로 구성한다. 새 실험은 대상 계층 → 프로토콜·하위 서비스 → 기본 시나리오 순서로 안내한다.

| 작업 공간 보기 | 중앙 내용 | 오른쪽 선택 항목 |
| --- | --- | --- |
| 실험 구성 | 계층, 참여자 A·B, 프로토콜과 하위 서비스 연결 | 서비스 요구사항, 보장사항과 호환성 오류 |
| 프로토콜 | 메시지·패킷 필드 표, 상태·변수 목록, 규칙 폼 | 선택한 필드·상태·규칙의 속성 편집 |
| 통신 환경 | 방향별 지연·손실·중복, 청크·연결 조건, seed | 설정 설명, 단위와 범위, 재현할 장애 |
| 시나리오·검증 | 최초 입력, 입력 시각, 관찰 기간, 기대 조건 | 입력 값 또는 조건 편집 |
| 실행 | 시퀀스, 가상 시간, 양쪽 상태, 실행 제어·실행 이유 설명 | 선택 이벤트의 원인·규칙·값·상태 변화 |
| 반복 실험 | 조건·seed·진행/중단, 두 묶음의 조건별 비교와 개별 기록 재생 | 하위 서비스 계약 |
| 시나리오 묶음 | 사례·기대 조건·환경 편집, 전체 검증·판정 변화 비교·기록 재생 | 하위 서비스 계약 |

상단은 실험 이름·원본/사본·저장 상태를 표시한다. 왼쪽은 보기와 구성 목록, 하단은 이벤트·진단·기대 조건 결과다. 같은 항목은 보기 간 선택을 연결한다. 오류를 선택하면 원인이 있는 편집 위치 또는 실행 이벤트로 이동한다. 목록과 규칙은 키보드로 선택·편집할 수 있고 색만으로 상태를 구별하지 않는다.

실행 중 편집은 일시정지 또는 실행 종료 후 새 초안에 반영하며 현재 실행 snapshot을 변경하지 않는다. 좁은 화면에서는 패널을 쌓거나 상세 패널을 전환하며 필수 작업이 가려지지 않게 한다.

## 범위 밖

실제 서버·기기 연결, 패킷 캡처, 전체 TCP/HTTP 구현, HTTPS·TLS, HTTP/2·3, 임의 바이너리 코덱, IP·링크·물리 계층 모델, 라우팅·다중 참여자, 여러 사용자 계층의 연결 실행, 실제 프로토콜의 성능 벤치마크, 계정·협업·클라우드 동기화는 후속 범위다. 범위 밖 항목을 자동으로 기술 부채로 등록하지 않는다.
