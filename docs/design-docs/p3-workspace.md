# P3 편집과 실행 작업 공간

상태: Accepted
기준일: 2026-10-30
P3 당시 구현 범위: 메모리 초안의 폼 편집, 이상적 환경의 실행·관찰, 진단 위치와 원인 규칙 연결. 이후 장애 모델·재전송·환경 폼은 [P4](p4-environments.md)에서 확장했다. 아래는 P3 당시 기준이며 표준 예제는 [P5](p5-standard-examples.md), 현재 내 실험/저장/기록 탐색은 [P6](p6-persistence-replay.md)가 확장·대체한다.

## 사용자 흐름

처음에는 편집 가능한 Ping/Pong 초안을 연다. 상단의 실험 시작에서 새로운 Ping/Pong 사본이나 빈 실험을 선택한다. 새 실험 선택은 현재 메모리 초안과 실행을 교체하며 화면에서 이 사실과 새로고침 보존 미지원을 안내한다. 저장된 내 실험 목록은 아직 제공하지 않는다.

| 보기 | 현재 동작 |
| --- | --- |
| 실험 구성 | 이름, 응용/전송 계층과 stream/datagram, 참여자별 정의 선택, 정의 사본 추가 |
| 프로토콜 | 메시지·필드의 ID/전송명/타입/배치/필수/기본값/범위/enum, 상태·변수·타이머, 규칙 편집 |
| 통신 환경 | seed, 방향별 고정 지연, stream 수신 청크 크기. 미지원 장애 설정은 노출하지 않음 |
| 시나리오·검증 | 입력 시각·참여자·메시지 값·생략, 전체 관찰 기간, 상태/전달 횟수/전달 내용/완료 기한 |
| 실행 | 전체·단계·일시 정지·초기화, 참여자 상태·변수·타이머, 실제 시퀀스·기대 결과·실행 진단 |

응용 계층은 JSON Lines stream 또는 JSON datagram, 전송 계층은 datagram 위의 논리 패킷을 사용한다. 계층·서비스 변경은 정의와 시나리오의 편집 내용을 유지하고 양쪽 코덱·버전·하위 환경을 호환되게 갱신한다. 전송 계층에서 stream 선택은 비활성화한다. 현재 서비스 계약 설명과 구현된 이상적 환경의 보장을 구분한다.

## 초안 편집과 검증

[edit-experiment.ts](../../src/application/edit-experiment.ts)는 JSON Pointer로 복사본을 편집한다. 정의 수정 시 revision을 증가시키고 이를 참조하는 참여자의 정확한 revision도 함께 갱신한다. 필드의 전송명과 참조용 ID는 별도다. ID 변경·삭제로 남은 참조는 자동 삭제하지 않고 P1 진단으로 드러낸다. 정의에 없는 입력·동작 값은 삭제할 수 있다.

[폼](../../src/ui/forms.tsx)은 label과 native input/select/textarea를 사용한다. 숫자·boolean·enum은 해당 타입으로 입력하고, 선언형 식의 고정 값과 변수 초깃값은 JSON 값으로 편집한다. 규칙은 입력/수신/타이머/연결 이벤트, 비교·all/any/not 조건과 재귀적인 값 식, 순서 있는 send/deliver/assign/타이머/finish 동작을 편집한다. 사용자 코드를 평가하지 않는다.

문법이 미완성인 JSON 텍스트는 마지막 유효 값과 별도로 메모리 초안에 보관한다. 보기 전환 후에도 텍스트·오류를 유지하고, 행 추가에서는 보존하며 행 삭제에서는 살아남은 행의 경로로 옮긴다. 실행은 모델 검사와 미완성 JSON 검사가 모두 통과해야 가능하다. 빈 실험도 메시지와 기대 조건을 정의하기 전에는 실행할 수 없다.

진단 버튼은 해당 보기·정의를 열고 정확한 data-path 컨트롤로 초점을 이동한다. 객체·참조 오류에 전용 컨트롤이 없으면 가장 가까운 편집 그룹으로 이동한다. 실행 중 참여자/규칙 진단은 현재 초안의 stable ID를 찾아 연결한다. 과거 규칙을 삭제하거나 ID를 바꾸었으면 이동 불가를 설명하며 당시 이벤트 상세를 유지한다.

## 실행 수명과 기록

[App](../../src/ui/App.tsx)은 [createRunSession](../../src/application/create-simulation.ts)으로 실행을 생성한다. 매 실행은 검증된 불변 snapshot을 사용하고 화면은 EngineView만 읽는다. 전체 실행은 짧은 timeout 사이에 유한한 runBatch를 진행해 브라우저에 제어를 돌려준다. 일시 정지·초기화·편집·교체·unmount는 예약 callback을 정리하고 runId로 이전 실행의 callback을 차단한다. React StrictMode의 effect 정리도 적용한다.

편집은 실행을 일시 정지하고 초안 버전만 바꾼다. 이전 기록은 이전 snapshot의 값이며 초안/실행 버전 차이를 표시한다. 다음 전체·단계 실행은 새 초안으로 새 run을 만든다. 같은 설정의 일시 정지 실행은 이어서 진행한다. 실행 초기화는 결과·선택·상태를 지우고 다음 실행은 독립적인 참여자로 시작한다.

[실행 보기](../../src/ui/RunView.tsx)는 실제 엔진 이벤트만 그린다. 송신, 하위 수신, 메시지 해석과 상위 전달을 구분하고 전이 데이터의 상태·변수 전후 값을 상세에 표시한다. 원인 이벤트와 규칙으로 이동한다. 목록은 최근 200개를 보여주며 선택한 원인 상세는 전체 메모리 기록에서 조회한다. 장기 기록 탐색·저장·성능 상한 검증은 P6/P7 범위다.

관찰 완료, 참여자의 성공/실패/오류와 기대 조건 통과/실패/미판정을 따로 표시한다. 타임아웃과 규칙 오류를 성공으로 숨기지 않는다. 런타임 계약·엔진 버전은 [P2](p2-runtime.md)를 유지한다.

## 검증 경계

[초안 통합 검사](../../tests/integration/workspace-draft.test.ts)는 세 코덱의 실제 예제, revision·snapshot 격리, 필드·조건 편집 영향, 프로필 호환성, 삭제 참조·JSON Pointer·미완성 값 이동을 검사한다. [Chromium E2E](../../tests/e2e/workspace.test.ts)는 브라우저 폼에서 빈 실험의 Ping/Pong 작성, 필드·조건 변경, 진단 초점, 관찰 결과·원인·규칙, 실행 제어·편집 중 정지·키보드·390px 흐름을 검사한다.

실행 결과와 명령은 [실행 계획](../exec-plans/completed/20261030-1641-layered-protocol-v1.md)에 기록한다. 원격 CI·배포·실제 서버/기기 통신, 장애 환경·HTTP/TCP·영속 저장은 P3 검증에 포함하지 않는다. 신규 production dependency는 추가하지 않았다.
