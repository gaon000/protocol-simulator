# P0 실행 계약과 개발 기반

상태: Accepted
확정일: 2026-10-30
구현 범위: 도구·작업 공간 골격과 기초 계약 함수·fixture. 전체 정의 검사·엔진·환경 실행은 P1 이후에 구현한다.

이 문서는 P0 완료 당시의 계약·검증 기록이다. 이후 구현된 정의 검사·코덱은 [P1 계약](p1-models-codecs.md)을 따른다. P0의 최소 JSON fixture는 당시 snapshot 복사 검증용으로 보존하고, 실행 준비용 전체 정의에는 P1 fixture와 유효성 검사를 사용한다.

## 도구 선택과 승인

Node 24.18.0, pnpm 9.15.0, TypeScript 7.0.2를 고정한다. React 19.3.1·React DOM 19.3.1은 사용자가 이 대화에서 production dependency 추가를 승인했다. Vite 8.3.5와 React plugin은 개발·빌드 도구, Biome 2.6.4는 lint·포맷 도구다. 코어 단위·통합 테스트는 Node 내장 test runner, 화면 smoke test는 Playwright 1.64.1의 Chromium을 사용한다.

React는 이후 필드·규칙 폼과 실행 상태를 연결하기 위해 선택했다. Vite는 backend 없는 단일 웹 프로젝트의 개발·빌드 도구로 사용한다. DOM 없이 코어 테스트를 실행하고, E2E에서는 dev mock이 아닌 실제 빌드 결과를 별도 preview 서버로 검사한다. Playwright와 문서 검사 패키지를 포함한 모든 검사 도구는 devDependency다.

지원 기준은 우선 로컬 Chromium smoke test다. 전체 브라우저 지원과 성능 기준은 P7에서 확정한다. CI·서버·배포는 이번 단계에 구성하지 않는다.

## 실행 순서와 시간

가상 시각은 정수 ms 단위이며 이벤트 키는 `(timeMs, priority, sequence)`다. 입력·전달·연결 이벤트의 priority는 0, 타이머는 1이다. 같은 시각·priority에서는 생성 순번을 유지한다. 따라서 500ms에 완전히 수신된 유효한 응답은 500ms timeout보다 먼저 처리한다. 499ms timeout은 500ms 수신보다 먼저 처리한다.

[기초 계약 함수](../../src/domain/execution-contract.ts)의 `compareEventKeys`와 [단위 테스트](../../tests/unit/execution-contract.test.ts)가 이 순서를 고정한다. 실제 이벤트 큐·규칙 처리·타이머 실행은 P2다.

타이머는 `(participant, name, generation)`으로 식별한다. 재시작·취소는 generation을 바꾸고 이전 큐 항목을 무시한다. 같은 입력에 두 규칙이 일치하면 중단·진단하며, 일치 규칙이 없으면 명시적인 무시 규칙이 있는 경우에만 계속한다. 이 정책은 `EXECUTION_POLICY`에 기록했으며 실제 전이 동작은 P1/P2에서 검증한다.

## seed와 난수

seed는 0을 포함한 uint32 정수다. 범위를 벗어나거나 소수·NaN·무한대면 거부한다. 알고리즘은 `mulberry32-v1`, 출력은 `[0, 1)`이다. 각 호출은 uint32 상태에 `0x6d2b79f5`를 더하고 기초 계약 함수에 고정한 정수 연산을 수행한다. 구현·호출 순서가 바뀌면 engineVersion을 바꾼다. 암호·보안 난수로 사용하지 않는다.

seed 42의 최초 네 출력에 2^32를 곱한 참조 값은 `2581720956, 1925393290, 3661312704, 2876485805`다. 단위 테스트가 이 고정 벡터와 독립 인스턴스의 재현성을 검사한다.

## 데이터그램 환경의 참조 계약

아래는 P4 구현을 위한 확정된 reference semantics다. P0에서 실제 네트워크 환경 엔진을 구현한 것은 아니다.

1. `(방향, 원본 전송 순번)`에 해당하는 특정 손실 조건을 먼저 검사한다. 해당하면 손실을 기록하고 난수는 소비하지 않는다. 최초 전송과 재전송은 서로 다른 원본 전송 순번이다.
2. 특정 손실이 없으면 손실, 중복, 원본 지연, 중복 지연 순서로 난수 4개를 항상 소비한다. 확률은 `[0, 1]`이며 `sample < probability`일 때 적용한다. 손실인 경우에도 이 4개는 소비하고 전달은 생성하지 않는다.
3. 생존한 패킷은 원본을 한 번 전달하고, 중복 조건이면 추가 사본 하나를 전달한다. 사본에 확률을 재귀 적용하지 않는다.
4. 각 전달 지연은 `max(0, baseDelayMs + round((2 × sample - 1) × jitterMs))`다. 전달 시각은 원본 전송 시각 + 지연이다. 같은 시각의 원본·사본은 원본 생성 순번이 먼저다.
5. 지연 차이로 사본이 원본보다 먼저 도착하거나 뒤의 패킷이 먼저 도착할 수 있다. 기록에서 각 전달을 원본 전송에 연결한다.

[참조 fixture](../../tests/fixtures/datagram-reference.json)는 seed 42, 전송 시각 100ms, 기본 지연 10ms, 변동 4ms, 손실률 0.1·중복률 0.5를 사용한다. 결과는 사본 111ms, 원본 113ms다. [참조 계산 테스트](../../tests/integration/environment-reference.test.ts)는 난수·산식을 검토하며, 실제 환경 구현의 검증은 P4에서 같은 fixture로 수행한다.

## 스트림 환경의 참조 계약

스트림은 방향별 바이트 순서를 유지한다. write마다 전송 지연을 적용하되 이미 예약한 바이트보다 앞서 도착하게 만들지 않는다. 같은 방향·같은 전달 시각의 write는 생성 순번으로 합친 뒤 양의 정수 `chunkBytes` 크기로 자르고 마지막 나머지를 전달한다. 서로 다른 전달 시각의 바이트를 미래의 합치기를 위해 기다리지 않는다.

수신 청크·write·메시지 경계를 동일시하지 않는다. 정상 EOF는 버퍼의 미완성 메시지를 진단하고, 연결 실패는 이미 받은 접두부와 별도 실패 이벤트를 전달한다. 이 동작은 아직 미구현이며 P1 코덱과 P4 환경 테스트로 검증한다.

## snapshot과 하위 서비스 포트

기초 `RunSnapshot`은 schemaVersion 1, engineVersion `0.1.0-p0`, 난수 버전, seed, 모든 설정의 JSON 사본, 실행 상한을 포함한다. `createRunSnapshot`은 `structuredClone` 후 재귀적으로 freeze해 초안 변경과 실행 설정을 격리한다. 반환 타입도 중첩 readonly다.

[설정 fixture](../../tests/fixtures/run-configuration.json)는 프로토콜 revision·실제 정의 내용·A/B 참조·환경·시나리오를 포함한 JSON 형태를 보여준다. 전체 메시지·규칙은 아직 완성하지 않았으므로 실행 가능한 프로토콜 예제로 취급하지 않는다. P1에서 스키마·참조·서비스 호환성을 검사하고 P2에서 실제 실행 상태를 만든다.

`LowerServicePort`는 stream의 바이트 배열 전송과 datagram의 논리 패킷 전송을 타입으로 구분한다. 구현체·DOM·저장 API를 참조하지 않는다. 현재 엔진이나 실제 서비스 어댑터는 없다.

## 기본 상한

| 항목 | P0에서 고정한 기본값 |
| --- | --- |
| 실행 이벤트 수 | 10,000개 |
| 단일 메시지 | 1 MiB |
| 참여자 수신 버퍼 | 각각 1 MiB |
| 이벤트 기록 | 실행당 16 MiB |

상한은 snapshot에 포함한다. 이 값들은 설정 계약이며 P0에서 실제 실행의 강제 중단을 검증한 것은 아니다. P1/P2에서 적용하고 P7에서 브라우저 측정 근거에 따라 조정한다. 상한 종료는 정상 성공으로 판정하지 않는다.

## 검증과 남은 단계

기초 계약·snapshot·문서 검사기의 Node 테스트와 strict 설정 음성 fixture를 제공한다. Playwright는 빌드된 작업 공간의 기동·계층/서비스 선택·보기 전환·좁은 화면을 검사한다. 현재 화면은 선택 상태를 메모리에만 보관하며 프로토콜 편집·통신 실행·저장은 제공하지 않는다.

실제 검증 명령과 결과는 [개발 기준](../development.md)과 [구현 계획](../exec-plans/active/20261030-1641-layered-protocol-v1.md)에 기록한다. 이 문서는 P1/P2/P4의 전체 엔진·환경 테스트를 대신하지 않는다.
