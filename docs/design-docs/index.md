# Design Docs

기능의 구조, 계약, 대안과 실패 경계를 구현 전에 검토한다. 제품 요구사항은 프로젝트의 요구사항 문서를 참조하고, 작업 진행과 실제 검증 기록은 실행 계획에 둔다.

## 사용

[템플릿](template.md)을 `<feature>.md`로 복사한다. 상태는 Draft, Accepted, Superseded를 사용한다. Accepted는 합의된 설계이며 배포나 구현 완료의 증거가 아니다. 실제 생성한 문서만 아래 목록과 프로젝트 문서 지도에 연결한다.

## 위험에 따른 검토

적용되는 항목만 설계 본문에서 다룬다. 단순한 화면 변경에 전체 분산 시스템 체크리스트를 요구하지 않는다.

- 상태를 바꾸는 진입점은 공개 API, 내부 호출, 관리자 작업, 삭제, 재시도와 callback까지 확인한다.
- 외부 호출은 transaction 경계, 시작 직전 유효성 확인, timeout, 중복 방지, terminal 처리와 늦은 응답 무시 조건을 정의한다. 요청 접수와 외부 동작 완료를 구분한다.
- 계산·응답·완료 처리에서 현재 데이터와 시작 시점 입력 중 무엇을 사용하는지 명시한다.
- parent·child 데이터의 유지·교체·삭제 정책, 소유 관계 변경·삭제 시 정리 시점과 stale 데이터 노출을 확인한다.
- 동시성·잠금·worker가 있으면 순서, 재시작, 재시도와 복구 기준을 적는다.
- 모듈 경계를 바꾸면 실제 호출·주입·설정 경로와 이를 검증할 방법을 적는다.
